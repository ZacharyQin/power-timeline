# Power Timeline

Steam Deck 的 Decky 功耗记录插件。采用 B「电池时间线」：QAM 快速看电量，完整页按同一时间轴查看电池、功率、游戏事件和会话历史。

## 使用

1. 打开 Decky → **Power Timeline**。后台启用后按约 1 秒采集，关掉 QAM 或详情页不会停止记录。
2. 选择「查看电池时间线」，切换最近 30 分钟、6 小时或今天；展开硬件域可看 APU、CPU、SoC、GPU。
3. 用原生读数滑块选择实际保留的样本。电池与功率共用游标；选择历史点后固定范围，不自动跳回最新数据。
4. 从游戏事件进入会话，或打开「游戏记录」查看分组与历次观测。返回保留范围、选择与焦点状态。
5. 已确认休眠用区间底色和“休眠”标记，虚线连接两端有效读数。连线只是视觉连接，不是休眠期间的实测或估算；缺失端点不补零，其他采集中断仍断线。
6. 主电池时间线以淡色背景显示游戏进程的实际观测区间，同一 AppID 保持同色。宽区间直接显示名称与 Steam 图标，短区间在图下图例识别；缺图显示手柄，不按名称猜图。图例仅列当前范围内的游戏，默认预览两款，更多游戏选择「全部 N 款」后每页六款，长名称完整换行。
7. 图下线样直接对应当前样本读数，硬件遥测单独分组；「颜色与读图说明」按需展开固定 W 分档及当前范围适用的说明。外接供电时直接解释电池侧方法无法计量整机，不重复显示多处“无有效读数”。
8. 游戏记录与历次会话的整行及尾箭头都是同一个入口；未知、中断或中途观测也可进入详情。页尾「统计说明」集中介绍统计规则，返回保留原页、范围、游标及分页状态。
9. QAM 充电时显示 UPower「预计充满」，充满显示「已充满」；未知、过期或外接未充电不会显示 0 分钟。选择「电源与电池详情」，或完整页顶端「电源与电池」，查看电池参数、容量信息、PD 契约与充电记录。

首次启用没有历史，不反推之前的耗电。游戏进程集合由后端实际发现；已在运行的游戏显示中途开始观测。插件中断前的会话与恢复后的观测分开，不补算缺口。

## 数字的含义

- **电量 %**：电池报告的百分比，变化量是百分点，不能直接换算为 Wh。
- **整机 W / Wh**：只在确认外接电源离线且电池放电时，由电流 × 电压和连续样本梯形积分得到。包含屏幕、系统与后台。插电时的电池净充电功率不是整机功率，整机项显示未知。
- **硬件域 W**：AMDGPU 遥测。APU 总量不与 CPU/SoC/GFX 分项相加。当前解码 `gpu_metrics` v2.4；未知版本、固件无效值和权限失败不是零。
- **游戏 CPU/GPU Wh**：`activity-weighted-v1` 的非校准估算，不是 Pulse 式每 PID 内核能量计。CPU 与 GPU 有效覆盖独立显示，覆盖可能不同，合计不提供伪造的平均功率。缺少任何域的可用值时，不把其补零成合计。
- **电池容量与健康信息**：mAh 来自电池上报；没有能量字段时，Wh 由电荷量 × 设计电压换算并明确标注。满充／设计比不截断为 100%；UPower 的容量估计不是另一份独立实测。不能确认的循环次数显示未知，不把固件占位 0 当成 0 次；不据这些字段推断完整健康状态。
- **PD 契约**：电压 × 电流是协商功率上限，不是充电器铭牌功率、实时输入或整机功率。未接电或契约为零时显示未知；不以它减电池净功率推算整机。
- **距上次充电结束**：从持久样本中连续观测到的 Charging → Full／Not charging／Discharging 边界起算，不是距上次拔电。重启从已有样本恢复；跨采样缺口、休眠、时钟跳变或未知状态时保留已知结束日期，但不伪造可靠经过时长。启用时间不充当充电结束。
- **预计充满**：只在电池确实 Charging、外接供电、UPower 状态匹配且来源更新不超过 90 秒时显示正数估计。随来源更新，可增加；不做本地递减倒计时。完整页可见时每 5 秒读取，QAM 可见且相关状态时每 15 秒读取；后端 UPower 查询最多每 30 秒一次，电池／供电状态变化立即刷新。关闭界面不保留额外订阅或轮询。

### 配色

- 曲线、短线图例和硬件域名采用固定身份色及线型；电量青绿，整机青蓝，硬件 APU / CPU / SoC / GPU 分色。功率数字另按原始有效 W 值分档，不随图表峰值、范围或口径归一化。
- W 五档：`0≤W<5` 蓝、`5≤W<10` 青蓝、`10≤W<15` 青绿、`15≤W<20` 淡金、`W≥20` 暖橙；边界进入新档，30/45W 以上仍显示真实值，不截断或自动报错。这是绝对量值显示，不是安全、效率或可信度评分。
- Wh 只区分整机实测与游戏进程估算；进程合计和 CPU/GPU 子项统一藕粉，不套用 W 色阶或硬件域身份色。未知保持中性，真实零与舍入为 0.00 的小值按原始值处理。
- 游戏背景色只识别游戏身份，不表示功率或能量大小，也不代表前台独占。区间按查询窗口裁切；运行中只画到最后一次实际观测，不延伸到“现在”，不生成采样、Wh 或有效覆盖。
- 聚焦字段的必要文字和短线样恢复原生前景，禁用滑块同样回退；其他区域不跟随退色。未聚焦彩色读数字段使用透明底，提高实际合成对比度，不修改全局主题。中断仅局部淡金，明确查询/记录错误才用红色。

### 估算模型

CPU 区间估算 = CPU 域能量 × 游戏进程 CPU 时间增量 / 全机 CPU 时间增量（含 idle）。不将空闲能量全部分配给游戏。

GPU 区间估算 = GFX 域能量 × 游戏 DRM 客户端执行时间占区间的比例。同一设备/client-id 去重；gfx 与 compute 取各自区间增量的较大值以避免直接重叠相加，多个游戏的合计权重超过 1 时归一化。AMD 驱动省略累计使用为零的引擎字段；未知驱动或不可读 FD 不视为零。

两种模型都受频率、电压、异步采样、功耗域平均窗口及并行/共享活动影响；不包含屏幕、SoC 等系统开销，也没有绝对误差保证。进程实例用 PID + 启动时间识别，进程集合变化的区间不冒充完整覆盖。多个游戏并行时，整机区间不完整复制给每个游戏。

## 存储与生命周期

- SQLite 和独占锁放在 Loader 的 `DECKY_PLUGIN_RUNTIME_DIR`；通常为 `homebrew/data/power-timeline/`，代码不硬编码用户主目录。
- 每样本一个短事务。图表降采样与能量账本分离，保留原始断段、空值边界和每连续段各域极值；休眠端点辅助线不生成采样或参与积分。点数无法覆盖原始边界时明确拒绝查询，可缩小时间范围。
- 默认数据库上限 **256 MiB**。达到上限停止记录并显示错误，保留历史，不静默删除。SQLite 回滚日志会临时占用额外磁盘；界面显示实际数据库及现存日志字节数，此上限不是整个文件系统的硬配额。
- 如需归档/重置，先禁用本插件，备份数据目录后再管理数据库；不要在采集者仍持锁时删除或改写数据库。升级不把数据库写进可替换的插件安装目录。
- 前端刷新、RPC 查询和关闭界面不会重启采集。后端重启中断旧会话并新建观测 epoch；崩溃尾段未提交的数据不补算。第二采集实例拿不到独占锁时拒绝写入。

## 开发与构建

基于 [官方 Decky 模板](https://github.com/SteamDeckHomebrew/decky-plugin-template)。Node/pnpm、TypeScript/React 与 `@decky/ui`/`@decky/api`，Python 后端仅使用标准库。

```sh
pnpm install --registry=https://registry.npmjs.org
pnpm typecheck
pnpm build
python3 -m unittest discover -s tests -v
```

安装包：[dist/power-timeline-0.1.0.zip](dist/power-timeline-0.1.0.zip)。根目录为 `power-timeline/`，包含 `plugin.json`、`package.json`、`main.py`、`LICENSE`、`README.md`、`dist/index.js` 和 `py_modules/*.py`；不含开发依赖、测试或本地数据库。通过 Decky 原生本地 ZIP 安装，不需要 root 标志或额外服务。插件名称为 **Power Timeline**，稳定目录标识为 `power-timeline`。
