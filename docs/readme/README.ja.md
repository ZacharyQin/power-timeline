<h1 align="center">Power Timeline</h1>

> “Steam Deck のバッテリー、劣化してきた？今は満充電でどれくらいの電気を蓄えられる？”
>
> “いつの間に電池が減ったんだろう？置いている間とゲーム中で、それぞれどれくらい使った？”

Power Timeline は Steam Deck 用の Decky プラグインです。バッテリーの満充電容量と設計容量を比べ、残量の変化、ゲームの実行、スリープの時間帯を一つの時間軸にまとめます。今のバッテリーがどれくらい蓄えられるかを見て、いつ電池が減ったのかを振り返れます。ページを閉じても記録は続きます。

この画像は、電源につないだ状態のクイックアクセスメニューです。今のバッテリー、小さな電力フロー、Steam の充電制限、過去 24 時間が見えます。画像のワット数は本体全体の電力ではありません。

<h2 id="what">見えるもの</h2>

**今のバッテリーはどれくらい蓄えられる？**

現在の満充電容量、設計容量、その比率を見比べると、容量が減っているかを考える参考になります。ここで見るのは満充電で蓄えられる量であり、今の残量ではありません。

**置いている間とゲーム中で、電池はどう減る？**

過去 1 日、3 日、7 日の残量の変化を、ゲームの実行、電源接続の変化、スリープの時間帯と照らし合わせられます。どこで大きく減ったのか、そのとき何をしていたのかを振り返れます。スリープ区間では前後の残量を比べられますが、区間中の連続測定や電力量の補完計算は行いません。ゲーム履歴では、各ゲームの電力量の推定も見られます。

クイックアクセスメニュー（QAM）では今の残量、小さな電力フロー、バッテリー情報を見られ、Steam の充電制限をオンまたはオフにできます。充電中でシステムが推定を出しているときは、満充電までおよそどれくらいかも分かります。

**セーリングモード**は電源・バッテリーページの電池情報の下に表示され、QAM には表示されません。初期状態はオフです。先に Steam の充電制限を有効にし、その値を上限として使います。モードをオフにして差分 Delta をパーセントポイントで設定し、下限は上限から Delta を引いて自動計算します。下限を個別には設定しません。例えば上限 80%、Delta が 10 ポイントなら下限は 70% です。区間内で有効化または電源を再接続した場合は待機し、下限以下で充電を要求して上限まで継続します。能動的な放電は行いません。

制御はページを閉じてもバックグラウンドで動作します。モードをオフにするかプラグインをアンロードすると元のハードウェア上限に戻します。Steam の設定変更時は新しい値を上書きせず制御を終了します。スリープ中に残るのは最後に設定した上限だけで、ファームウェアの二段階制御ではありません。完全な充電サイクル、スリープ復帰、再起動の実機検証は未完了です。単体テストはその証拠にはなりません。

下部の **QAM コンポーネントの順序**から、別のダイアログを開かず、QAM 上で全 10 項目を並べ替えます。上下で選び、**A** で持ち上げ、上下に動かして **A** で置きます。**B** は今回の移動を取り消し、何も持ち上げていない場合は編集中の変更をすべて破棄します。**X** で保存して終了し、**Y** で編集中の順序を初期状態に戻します。キーボード操作も標準のフッターに表示されます。編集中も元の内容は見えますが、通常の操作は無効になります。タッチやマウスでは項目を選び、その中の移動ボタンを使えます。非表示の項目も名前付きの位置を保持します。保存した順序はこの Deck に記憶され、新しい項目は末尾に追加されます。

**ファン制御**は QAM の既存のファン曲線と同じ項目に表示されます。ファンアイコン付きの見出しの下には、**システム自動**と**最大回転数**の二つのタブだけを表示し、L1/R1 の案内、ドロップダウン、RPM の行、説明段落は置きません。左右ではフォーカスだけを移動し、**A** で確定してからモードを切り替えます。完全な対応グラフは確定済みの自動モードでのみ表示し、最大モードでは非表示になります。フォーカス移動だけでは表示状態は変わりません。保存した位置は維持されます。最大は 7300 RPM を要求しますが、実測値が同じになる保証ではありません。

QAM を閉じても最大制御は継続します。自動への切替やプラグインのアンロード時は、元の OS または EC の自動制御へ戻します。独立した systemd プロセスと終了時の清理でバックエンド切断に対応し、低消費電力ダウンロードモードや検出した外部制御を優先して上書きしません。公式の曲線やサービスの有効化設定は変更しません。logind の遅延ロックでスリープ前の復元を要求し、再起動後に最大を自動再開しません。制御されたスリープ／再起動と実物のコントローラー／タッチ操作の検証は未完了です。

<h2 id="install">インストール</h2>

### 先に Decky を入れる

Decky がまだなら、公式の [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader#installation) の手順で入れます。同じ手順は [wiki](https://wiki.deckbrew.xyz/en/user-guide/install) にもあります。

### パッケージをダウンロードする

[最新の Release](https://github.com/ZacharyQin/power-timeline/releases/latest) を開きます。名前が `power-timeline-` で始まり `.zip` で終わるファイルをダウンロードします。Source code (zip) は取らないでください。あれはソースで、Decky にはインストールできません。

別のパソコンで ZIP を落とした場合は、先に Steam Deck へコピーします。

### Decky でインストールする

下のメニュー名は、Decky の日本語画面にある文言です。このプラグインはストアにないので、ZIP から入れます。

1. クイックアクセスボタンを押し、メニューを開いてプラグのアイコンへ移動します。見出しは Decky になっているはずです。すでにプラグインの中にいるときは、見出しの左にある矢印で Decky に戻ります。
2. 歯車を選びます。ヒントは「Decky設定を開く」です。
3. 「一般」を開きます。「その他」で「開発者モード」をオンにします。
4. 左の一覧に「開発者」が出ます。それを開きます。
5. 「サードパーティプラグイン」の「ZIPファイルからプラグインをインストール」で「開く」を選びます。
6. Decky がこのプラグインを審査していない、という案内が出ます。最初は約 5 秒待たないと先へ進めません。
7. 名前が `power-timeline-` で始まる ZIP を選びます。

入ったら、プラグのアイコンの下の一覧に戻り、**Power Timeline** を開きます。

バックエンドはハードウェアを読むために root で動きます。システムの電源方針を自分から変えたり、ほかのプラグインを変えたりはしません。

### 更新と削除

更新するときは、同じ最新 Release のページから新しい `power-timeline-` の ZIP を取り、上の手順でもう一度入れます。

削除は Decky 設定の「プラグイン」で行います。削除しても履歴は消えません。履歴は通常 `~/homebrew/data/power-timeline/` にあります。履歴も消す場合は、そのデータディレクトリを削除できます。

履歴はサンプルごとの JSON ではなく、SQLite の数値列、文字列辞書、エラーと理由の関連テーブルで保存します。旧 JSON データベースの更新時は別の新データベースを検証し、完全な `timeline.pre-typed-*.sqlite3` バックアップを残してからアトミックに切り替え、精度は落としません。0.3.3 以降、使用中のデータベースは最大 256 MiB です。満杯になると記録順に最も古い一群と関連データを削除し、空きページを再利用して記録を継続します。切り詰められたセッションは一部の記録と表示し、保持された区間のみを集計します。最新のサンプルは残します。バックアップは自動削除せず、バックアップとトランザクションログは別途ディスク容量を使います。旧版へ戻すときはプラグインを停止し、対応する旧データベースも復元してください。コードだけを戻さないでください。

<h2 id="try-it">最初の使い方</h2>

1. クイックアクセスメニューを開き、プラグのアイコンへ移動して **Power Timeline** を選びます。
2. 「過去24時間」に焦点を移し、確認ボタン（A）でバッテリーの時間軸を開きます。
3. ページ上部で「過去1日」「過去3日」「過去7日」を選びます。曲線に焦点を移し、左右で時刻を見ます。その時刻の残量と電力が表示されます。ゲームを記録していたときは、アイコンと名前も出ます。
4. 「ゲーム履歴」を選びます。
5. クイックアクセスメニューに戻ってから、小さな電力フローを選んで確認ボタンを押すと電力フローが開きます。「バッテリー」を選んで確認ボタンを押すと、電源とバッテリーが開きます。

最初に有効にしたときは、それより前の記録はありません。有効にする前の使用量も埋めません。

曲線の表示点数は QAM で最大 288 点、時間軸とセッション詳細で最大 600 点です。上限内で実測の始点・終点、境界、極値を残します。すべてを残せない場合も、省いた境界をまたいで線をつながず、連続性を作りません。イベント、電力量、記録済み時間は引き続き履歴全体から求めます。

<details>
<summary>タッチとその他の操作</summary>

- 「過去24時間」をタップすると時間軸が開きます。小さな電力フローをタップすると電力フローが開きます。「バッテリー」をタップすると電源とバッテリーが開きます。
- クイックアクセスメニューの 24 時間の小さな図で左右を押すと、一時的な印が動くだけで、時間軸には入りません。
- 時間軸の曲線では、横に滑らせると時刻が選ばれます。滑らせずにタップしただけでは選ばれません。

</details>

<h2 id="limits">注意</h2>

- 本体全体の電力は、バッテリーが放電していると確認できたときだけ分かります。電源接続中は不明です。充電電力、バッテリーの正味電力、APU の電力では代わりません。
- ゲームの電力量は推定です。二つのゲームが同時に動いていても、それぞれに本体全体の電力量が割り当てられるわけではありません。
- 測れなかった数は不明のままです。0 にはしません。満充電までの時間はシステムの推定であり、正確なカウントダウンではありません。
- 充電制限は、Steam にすでにあるスイッチをオンまたはオフにするだけです。パーセントは Steam で変えます。
- 記録は機器に残り、送り出しません。
- Steam Deck 1 台（Galileo）で試しています。ほかの機種は未確認です。

<details>
<summary>電力量の推定に含まれるもの</summary>

ゲームの電力量の推定は、プロセスの活動で分けられる CPU と GPU のエネルギーです。そのゲームを動かしているときの本体全体の電力量ではありません。画面、別に読み取った SoC の電力、そのゲームに割り当てられなかったシステム分は含みません。

</details>

<h2 id="language">言語</h2>

自分で選ぶまでは、Steam の表示言語に従います。

簡体字中国語、英語、ポルトガル語、スペイン語、日本語、韓国語から選べます。初期設定ではクイックアクセスメニューの下部近くに国旗が並び、各ページでは引き続き一番下に表示されます。左右または横滑りはハイライトだけを動かします。確認すると切り替わります。案内はその旗の言語です。選んだ言語は覚えておきます。

この文書も同じ六言語です。先頭のリンクで切り替えます。

<details>
<summary>ソースからビルドする</summary>

Node.js、pnpm、Python 3 が必要です。

```sh
pnpm install --registry=https://registry.npmjs.org
pnpm typecheck
pnpm build
python3 -m unittest discover -s tests -v
```

`pnpm build` がフロントエンドを作ります。実行に必要なファイルを ZIP に入れてからインストールします。データベースはプラグインのディレクトリに置かないでください。

</details>
